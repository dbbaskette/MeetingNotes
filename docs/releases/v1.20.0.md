# MeetingNotes 1.20.0 — delete unwanted captures, Obsidian vault fix

## Delete unwanted captures from the app

Capture files are all named `recording-<time>-<id>.m4a`, with `.voice` and
`.system` companions, so finding a bad one in Finder was guesswork. Each row in
**Needs attention → Capture recovery** now has **Delete…**. It lists that
recording's files by what they hold (combined recording, your microphone, app
audio) with their sizes and names, then moves them to the macOS Trash and removes
the row. You can put them back from the Trash in Finder until you empty it.

- Only the files of that recording are touched. If a Library meeting uses any of
  them, nothing is deleted and the row says which file is in use.
- When no files are left on disk, the button reads **Remove from list**.
- Rows now show when the capture started (for example "Tue, Nov 3, 2:05 PM")
  instead of only its age. **Finder** is now **Show in Finder**.

## Obsidian vault availability

Fixes Obsidian sync reporting “Vault is unavailable or was replaced” for an
existing, correctly configured vault after a reboot or remount changes its disk
device number. This also fixes preview rejecting the same valid destination.

Recovery requires both the original vault and managed sync folder to retain
their folder IDs, a consistent device-number change, and the exact library and
destination ownership marker. Obsidian metadata, the Notes folder and write
access must still be present. Missing folders, symlinks, changed folder IDs,
different owners and inconsistent devices remain blocked. No folders are adopted
or recreated as part of this recovery.

Preview remains read-only. A normal enabled sync batch refreshes the stored
identities only after all checks succeed, then resumes the existing export.
Your vault path and existing notes need no manual changes or reconfiguration.
See the [Obsidian verification record](https://github.com/dbbaskette/MeetingNotes/blob/v1.20.0/docs/reviews/2026-10-23-obsidian-device-identity.md).

## Upgrading

Install 1.20.0 over 1.19.x. No database schema migration is added. Includes the
1.19.1 startup hotfix. Apple silicon and macOS 26+ remain required. Local
installers use the existing Apple Development signature, without Developer ID
notarization. GitHub publishes source and release notes without binary attachments.
