# MeetingNotes 1.12.7

**Release date:** 2026-09-30

MeetingNotes can now remember corrections to recurring terminology, such as **Salsa → SLSA**, and reuse them in transcripts and meeting notes. Corrections remain local and under your control. This GitHub release is source-only; the Apple Silicon installer is built locally, not attached to GitHub.

## Highlights

### Remember a correction once

- After saving a short word or phrase correction in notes, an inline **Remember correction** offer lets you save it without interrupting editing. Large rewrites are not treated as dictionary entries.
- Save a rule for the current group or the entire library. Group scope helps keep technical terminology from affecting unrelated meetings.
- **Suggest** is the default. Automatic replacement requires explicitly enabling it. You can skip an offer or turn learning offers off in Settings.

### Review and correct transcripts and notes

- **Correct term…** previews matching occurrences before applying a change. Select the occurrences you want, apply or dismiss suggestions, and inspect correction history.
- Supported corrections can be undone. Revision and context checks reject stale previews and ambiguous undo attempts instead of overwriting newer edits.
- Transcript corrections survive speaker-naming remerges. Raw transcription, speaker identities, timestamps, and audio remain unchanged.
- Correcting a transcript marks existing notes as stale. Regeneration is explicit and warns that it replaces notes and action items; correcting terminology does not silently regenerate them.

### A manageable local dictionary

- Settings includes searchable terminology rules with Add, Edit, Disable, and Delete controls.
- Rules support group/library scope, case sensitivity, and Suggest/Automatic modes. Validation rejects conflicting rules and replacement cycles.
- Automatic rules apply during transcript merging and summary generation. A bounded glossary also guides summary generation; automatic matching is deterministic and does not rely solely on the model following that guidance.
- Matching targets prose and protects supported Markdown code, links, and transcript labels. Rule changes do not retroactively rewrite all existing meetings.
- Recoverable artifact writes and revision checks protect correction state across interrupted writes and detect external changes before overwriting files.

## Upgrade and rollback

- Requires macOS 14.2+ on Apple Silicon. Back up the complete meeting library before upgrading, including its SQLite database and meeting artifacts.
- Database migration **18** adds terminology rules, preferences, and per-document correction state. These live in the existing local library database; no new cloud service or model request is introduced.
- Existing meetings are not bulk-rewritten on upgrade. Audio capture and speech-to-text prompting are unchanged.
- Retain the previous installer and pre-upgrade backup. Installing older code does not reverse migration 18 or undo corrected artifacts. For a full rollback, restore the matching pre-upgrade library backup while the app is closed. Older versions do not manage the new correction history.

## Build locally

```bash
git clone https://github.com/dbbaskette/MeetingNotes.git
cd MeetingNotes
git checkout v1.12.7
npm install
npm run dist
```

Expected outputs: `release/MeetingNotes-1.12.7-arm64.dmg` and `release/MeetingNotes-1.12.7-arm64-mac.zip`. GitHub does not carry these binaries.

## Known limitations

- The local app uses an Apple Development certificate. Apple notarization is not configured; the installer is not claimed as notarized.
- Learning is intentionally limited to short substitutions. Large edits can be corrected through **Correct term…** or Settings instead. Large previews and matching work are bounded.
- Undo can be refused when intervening edits make an occurrence ambiguous. Disabling or deleting a rule does not revert previously applied corrections.
- Terminology is not a general transcript editor and does not change the speech-to-text model's vocabulary. Protected Markdown handling is conservative rather than a full document round-trip editor.
- The experimental remote-processing beta remains separate. The production renderer still lacks a Content Security Policy.
