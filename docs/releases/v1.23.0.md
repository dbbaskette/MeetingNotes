# MeetingNotes 1.23.0 — an optional high-accuracy engine, calendar titles, and Ask inside a meeting

## Optional WhisperKit transcription

**Settings → Processing → Transcription engine** now offers a second engine next
to Apple Speech: **WhisperKit Large-v3-Turbo (High accuracy)**. It runs OpenAI's
Whisper large-v3-turbo as a Core ML model inside the same helper that already
does speech. There is still no Python, no server and no account or token.

- Apple Speech stays the default. Choosing WhisperKit downloads nothing by
  itself; **Prepare native speech** downloads about 627 MB, checks every file
  against a pinned hash, and loads the model once so macOS can optimize it.
- Processing never downloads. If the model is missing, the run stops with a
  message asking you to download it or switch back.
- It is slower than Apple Speech. On an M-series MacBook Pro, 104 seconds of
  clean synthetic speech took about 7 seconds with WhisperKit and about 1 second
  with Apple Speech. In that test WhisperKit spelled every name and product term
  correctly and Apple Speech did not. One synthetic voice is not a benchmark;
  try it on your own meetings.
- Your Dictionary replacements and roster names are given to the engine as
  vocabulary. With WhisperKit this changes spellings. Apple Speech accepts the
  same list, but on macOS 27.0 it made no difference in testing.
- Each run records the engine it used, shown in the meeting's processing
  details. Reprocess a meeting to transcribe it again with the other engine.

See [Models](../guide/models.md#optional-whisperkit-for-higher-accuracy).

## Calendar-aware recording

Turn on **Settings → Recording → Calendar** and a recording started during a
calendar event takes the event's title. The event's attendees are offered as
name suggestions in speaker review, under "From the calendar invite".

- Off by default, read-only, and nothing leaves the Mac. macOS asks for
  calendar access only when you turn the setting on.
- A title you type, a title passed by URL, or a later rename always wins.
- Recording never waits for the calendar: capture starts at once and the title
  arrives a moment later.
- Attendee names are suggestions. No voice is ever named from the calendar
  without your click. All-day and declined events are ignored.

This release has not been tried against a real calendar with access granted;
the steps to check it are in the
[manual smoke test](../manual-smoke-test.md).

## Ask

- **Ask inside one meeting.** An "Ask about this meeting" box sits above the
  tabs. A transcript citation jumps the player to that moment; a notes citation
  opens Notes. When nothing relevant is found, it says so.
- **Ask across the Library now follows your filters.** With filters active in
  ⌘K, the answer comes only from the matching meetings and says which scope it
  searched.
- **It says where the question went.** A model on this Mac is labelled as such.
  With a remote endpoint, the answer names the host that received the question
  and the quoted passages.

## Recording

- **A silent recording asks before it stops.** After two minutes with no audio
  the app shows a countdown with **Continue recording** and **Stop now**, in
  the Library, on the recording pill, in the menu bar and as a notification.
  Both times are adjustable in Settings → Recording.
- **Live capture status survives switching views.** Leaving the Library during
  a recording no longer raises a false "no audio" warning.
- A source that never delivered any audio gets its own warning, separate from
  quiet participants. "Restart with All system audio" keeps your microphone
  choice. The meeting-detected banner shows on every view.

## Notes, tasks and voices

- **Tasks keep their owners.** Extracted action items lost their owner on
  save; they keep it again. When you name a voice after the notes were written,
  its tasks now count as yours in Weekly and Actions.
- **Voices to name.** Finished meetings that still have unnamed voices appear
  in Needs attention. After you name one, the notes panel offers to regenerate
  notes that were written with `SPEAKER_00`-style labels.
- **Meeting page.** Cancel a run from the page or the status bar, choose a
  notes template before first processing, save notes with ⌘S, copy them as
  Markdown, and filter the Actions tab by All, Open, Done or Mine. Find in the
  transcript highlights its matches.
- **Model thinking** is a four-level setting (Off, Minimal, Low, Model default)
  and now also suppresses reasoning in models that use `reasoning_effort`.

## Fixed

- **LM Studio with too small a context.** A model already loaded with a smaller
  context than configured is reloaded in managed mode, and a context overflow
  is explained instead of reported as a generic failure.
- **The model picker was empty** when the managed LLM server was not running.
  It is started before models are listed.
- **Cancelling during notes** took effect only after a retry delay. It is
  immediate, and errors name the provider you actually use.
- **Deleting a meeting that is being processed** is refused with guidance; a
  queued one is removed from the queue.
- **Recordings with `#`, `?`, `%` or spaces in their path** now play.
- **Readable controls.** Primary buttons in dark mode, the speaker-review
  Continue button, the "running long" label and speaker avatars failed contrast
  guidelines; all now pass. Dialogs, menus and the notes editor work properly
  from the keyboard.

## Faster

- Search no longer checks every meeting folder one at a time, and large
  libraries are searched with a single pass.
- The window appears before the folder watcher, Obsidian sync and Trash cleanup
  start. The Library re-renders far less while meetings are processing.

## Removed

- Four settings that had no effect: the AAC bitrate (recordings are always
  128 kbps), `exporterApple`, `exporterMarkdown` and `audioHijackSessionName`.
- The speech-comparison beta is no longer packaged inside MeetingNotes.app. It
  is still built separately with `npm run dist:beta`.

## Upgrading

Install 1.23.0 over 1.22.x. The first launch applies three small database
changes: two indexes, and tables for the regenerate prompt and calendar
events. Existing meetings are untouched. The app gains the Calendars
entitlement, which is used only if you turn calendar awareness on.

Apple silicon and macOS 26+ remain required. Local installers use the existing
Apple Development signature, without Developer ID notarization. GitHub
publishes source and release notes without binary attachments.
