# MeetingNotes 1.14.10

2026-10-12. Weekly summaries are now permanent saved reports instead of
invalidatable caches. Starting a new week or editing your meetings no longer
requires regenerating previously generated summaries. GitHub publishes source
and release notes only; Apple Silicon installers are built locally.

## Permanent weekly reports

- **Save the entire report:** overview, cross-meeting themes, decisions,
  meeting titles/recaps/durations, and grouped open actions are stored together
  as a SQLite snapshot when generation succeeds.
- **Reopen without regenerating:** new meetings, summary corrections, task
  completion, speaker renaming and changes to your "You are…" setting do not
  invalidate an existing report. Reports survive app restarts, new weeks and
  year boundaries, and remain readable when the model is offline or source
  meetings have been removed.
- **Explicit updates only:** Regenerate builds a replacement from the latest
  meeting notes and tasks. The saved overview, themes and other sections stay
  visible while replacement is pending and after a failed attempt. The old
  report is replaced only after successful generation and source validation.
- **Consistent Markdown export:** exports use the same saved snapshot, not a
  saved overview combined with today's meeting/task data. Exported reports
  identify their generation date and historical action status.

## Clear historical versus live information

- Generated weeks display a **Saved report** badge and a brief explanation of
  when their contents change.
- Saved actions are labeled historical and read-only. Use their source-meeting
  links to manage current tasks without rewriting a historical report.
- Current-week meetings and tasks still update live. Task completion, owner and
  due-date edits, Snooze, save rollback and Retry remain available there.
- Mine, Overdue and Due this week filters in saved reports use the snapshot
  date, so their classification does not drift as later weeks pass.
- Current-week narrative generation remains unavailable until the week ends.
  Concurrent first-generation/replacement requests coalesce. Relevant source
  changes during generation reject the replacement without erasing the old
  report; unrelated speaker additions no longer invalidate generation.

## Existing summaries and database upgrade

Schema migration **23 → 24** adds a nullable structured-snapshot column without
deleting meetings, tasks, recordings or existing weekly narratives. Reports
generated by older versions keep their original overview, themes, decisions and
generation date—no model call is needed to preserve them.

Older versions did not store historical meeting/action sections. Those sections
are captured once from the available data when an older report is first opened
after upgrading, with an explanatory notice and separate capture date. This
cannot reconstruct already-deleted source data or historical task status.
Choose Regenerate if you want a new report entirely based on current inputs.
Older reports remain visible and exportable even if no source meetings remain;
an attempted regeneration explains why it cannot replace them.

## Install, check and rollback

The local DMG/ZIP targets **Apple Silicon, macOS 14.2+**, uses the existing
**Apple Development** signing identity and is **not notarized**. Building it
does not install it or interrupt recording/processing. Finish active work and
quit MeetingNotes before replacing the app; keep a complete Library backup.

After installing, verify version **1.14.10** and open an older weekly summary.
It should appear as a saved report without starting the model. Edit a source
meeting or complete a task, then reopen/export the report: it should stay the
same. Regenerate should intentionally update it. With the model unavailable,
a failed regeneration should retain the previous report. Current-week task
controls should still work.

An app downgrade does not reverse migration 24 or restore overwritten report
content. Older versions again apply cache invalidation and do not understand
the structured snapshots. For rollback, preserve the current Library separately
and restore a complete pre-upgrade backup with the previous installer rather
than assuming an older app will undo the data upgrade.

The microphone timing fix from
[1.14.9](https://github.com/dbbaskette/MeetingNotes/releases/tag/v1.14.9) is
retained; this patch does not change recording, transcription or diarization.
