# MeetingNotes 1.14.8

2026-10-09. Smoother processing, more room for notes, meeting-specific templates,
menu-bar controls and stronger security foundations. This release includes all
changes merged since [1.14.7](v1.14.7.md). GitHub publishes source and release
notes only; Apple Silicon DMG/ZIP installers are built locally. The experimental
remote-processing beta remains separate.

## Processing without interruptions

- **One Library scroll area:** the attention inbox and meeting rows no longer
  compete for scrolling or squeeze the meeting list to almost zero height in a
  short or zoomed window. Both Organized and All meetings retain bounded row
  rendering. Stage refreshes preserve the current scroll position.
- **Open progress while selecting:** processing and speaker-review meetings
  open on click or Enter even when other meetings remain selected. Their
  checkboxes still support explicit selection.
- **Process directly:** bulk Process refreshes the selected meetings' statuses
  and queues only those still pending, without a blocking confirmation or
  redundant success popup. Successful starts leave selection; failures remain
  selected for retry. Duplicate submissions are prevented while queueing.
- Routine queue feedback auto-clears without locking the Library. Inline
  processing status remains visible. Delete and re-run confirmations stay in
  place, and active recording Stop controls remain reachable while scrolling.

## More useful meeting notes

- **Six built-in notes templates:** General, 1:1, Standup, Customer call,
  Interview and Decision review. Choose a default per group in Settings →
  Processing, or override one meeting in **Processing ▾ → Notes template**.
  Automatic follows the group. All templates retain Overview, Decisions,
  Action Items and Off-topic Conversation for downstream features.
- Changing a template does not rewrite existing notes. Explicitly re-run
  **Notes and action items only** to apply it to a finished meeting; previous
  notes remain in history. Custom templates and cross-meeting chat are not
  included.
- **A wider meeting page:** date and duration move into the header, while
  models and re-run actions sit behind **Processing ▾**. The speakers/export
  rail can be hidden, and its preference is remembered. More than four named
  voices fold into one expandable row; voices needing review remain visible.
- Existing one-operation terminology corrections across transcript and summary
  are retained, including combined Undo and the shared dictionary.

## Capture from the menu bar

- A menu-bar item shows elapsed recording time and offers recording, Stop,
  processing Pause/Resume and Open MeetingNotes controls. It is enabled by
  default and can be hidden in Settings → Recording.
- An optional global shortcut starts all-system-audio capture with the
  microphone, or stops the current recording. It is unset by default. Invalid
  or unavailable shortcuts do not replace the previous working shortcut.
- These controls reuse the recorder's existing single-capture reservation and
  do not steal window focus. Calendar awareness is not part of this release.

## Security, reliability and documentation

- Electron advances from 30 to **44.7.0**, with refreshed native/dependency
  builds. Windows explicitly use sandboxing and context isolation.
- App navigation is contained; approved external links open in the default
  browser, and new Electron windows/webviews are refused. Production builds
  enforce a Content Security Policy without inline scripts or eval.
- Stored webhook and Google client secrets use macOS-backed encryption;
  renderer settings receive masks rather than the saved values.
- Every IPC channel validates arguments through a shared schema table, backed
  by contract tests. Renderer failures have recovery/error screens rather than
  leaving a blank window; diagnostics record useful error context.
- The README and task-focused guides are rewritten, screenshots refreshed, and
  documentation checks catch broken links and stale version/runtime badges.
  Tests run under Electron's Node to share one native SQLite build, and local
  CI enforces whole-repository lint with zero warnings.

## Upgrade and rollback

Quit MeetingNotes and keep a complete Library backup before replacing the app.
Include the existing settings database and meeting files. Building an installer
does not install it or interrupt an active capture.

Compared with 1.14.7, database migration **23** adds nullable notes-template
columns to groups and meetings. No recording/audio files are relocated. Earlier
plaintext webhook and Google client secrets are encrypted on startup. An older
build cannot interpret the encrypted values; if rolling back, use the pre-upgrade
backup and re-enter credentials as needed. Encrypted secrets restored on another
Mac also need re-entry. Do not assume an app downgrade reverses data changes.

No live meeting, real capture, model-output quality, signed-in export or actual
Library upgrade is claimed by these synthetic tests. Installer VM testing is
intentionally omitted at the owner's request. The local installer uses the
existing **Apple Development** identity and is **not notarized**; this is not a
notarized public-distribution build. Requires macOS 14.2+ on Apple Silicon.
