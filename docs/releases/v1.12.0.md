# MeetingNotes 1.12.0

**Release date:** 2026-09-09

This GitHub source release records the completed 1.12.0 update. The Apple Silicon DMG and ZIP were already built and verified on September 8; no installer rebuild is required for this publication. Binary assets are intentionally not attached to GitHub. Existing installer recipients can continue using those artifacts; source users can build locally using the instructions below.

The experimental 1.13.0-beta.1 remote-processing branch is separate and is **not included** in this release. Recording and processing in 1.12.0 remain local.

## Highlights

### Faster, clearer capture recovery

Recovery inspections are cached and streamed instead of repeatedly probing every abandoned capture. Large recovery inboxes open and refresh more quickly while retaining accurate duration, repair, and audio-usability status.

Damaged or accidentally overlong recordings can now be previewed before recovery and trimmed to a selected range. Trimming writes a separate recovery input and preserves the original capture, so the operation remains reversible until the user deliberately removes the source.

### Meeting details load on demand

Opening a meeting no longer synchronously reads and parses every transcript-related artifact. Summary content is available immediately, while transcript and speaker artifacts load asynchronously only when their views need them.

Parsed artifacts are cached with generation-based invalidation. Missing artifacts are handled normally, while malformed or temporarily unreadable files remain visible as retryable errors instead of being cached as empty results.

### A Library that scales

The Library now uses stable keyset pagination, scoped metadata enrichment, and virtual row rendering. Search, filters, counts, Needs Attention, live pipeline updates, selection, bulk processing, deletion, and Undo continue to cover the complete library rather than only the currently loaded page.

Renderer invalidations and global attention hydration are serialized and coalesced, preventing event bursts from publishing stale state or multiplying background requests.

In the fixed synthetic 10,000-meeting benchmark:

- initial payload fell from 7,231,327 bytes to 36,793 bytes (99.49% smaller);
- first-page loading improved from 66.273 ms to 1.247 ms (53.1× faster);
- a 1,000-row Library mounted 15–21 rows instead of all 1,000;
- initial React work fell from 92.3 ms to 4.5 ms; and
- continuation after 9,900 rows completed in 1.367 ms median end-to-end across seven samples.

These are synthetic local measurements, not production latency guarantees. Global counts, global Needs Attention coverage, loaded-prefix refreshes, and exact cross-page selection remain proportional to their result sets.

## Upgrade notes

- Requires macOS 14.2+ on Apple Silicon.
- Existing meetings, recordings, settings, action items, and speaker links remain in place.
- The Library browse index is added automatically during database migration.
- A local LLM runtime and the existing Whisper/pyannote setup remain unchanged.
- Back up the meeting library before upgrading. Keep the original recordings and prior installer; if rolling back, preserve the library rather than deleting it or manually reversing migrations.

## Build locally

```bash
git clone https://github.com/dbbaskette/MeetingNotes.git
cd MeetingNotes
git checkout v1.12.0
npm install
npm run dist
```

The installer artifacts are generated at `release/MeetingNotes-1.12.0-arm64.dmg` and `release/MeetingNotes-1.12.0-arm64-mac.zip`.

## Known limitations and security status

- The production-only audit result above does not include Electron or all build tools, even though Electron is shipped in the app. The subsequent full dependency review found existing advisories; this source publication does not claim a vulnerability-free packaged runtime or production security qualification.
- The production renderer still lacks a Content Security Policy. Runtime/toolchain upgrades and CSP hardening need separate compatibility verification.
- Library counts, global Needs Attention coverage, loaded-prefix refreshes and exact cross-page selection are not constant-time operations; the synthetic measurements above are not guarantees for every library or machine.
- No Cloud Foundry service or remote-processing capability is introduced by this stable release.
