# MeetingNotes 1.16.0 — native speech, without the legacy setup

This release makes a clean break: Apple SpeechTranscriber and SpeakerKit are the only speech engines in the regular app. It requires **Apple silicon and macOS 26 or newer**. Reinstall 1.15.0 to return to the old engines; there is no in-app fallback.

## Removed

- Whisper default/provider selection, model management/downloads, custom STT URLs and remote transcription transport.
- Hugging Face token/gated-model setup and its IPC endpoints.
- Python pyannote sidecar, Python/PyTorch installer payload, build prerequisites, local speech-server supervisors and legacy vector matcher.
- Obsolete conversion/chunking and Whisper-specific hallucination filtering. Native speech consumes the same mixed recording for transcription and diarization.

## Simpler setup

The wizard now has three steps: capture permissions, **Prepare native speech**, and summary-runtime setup. Every installation uses native speech, including upgrades with old Whisper settings. Native asset preparation is explicit, cancellable and retryable; opening Settings never starts a download. Setup health reports Apple language and SpeakerKit assets separately.

Internet is still needed once for Apple-managed language assets and about 11 MB of integrity-verified public SpeakerKit models. The public models are hosted on Hugging Face without an account/token. SpeakerKit contains WhisperKit audio utilities and pyannote-family Core ML models, not Whisper ASR or the Python runtime. Summaries still need a configured LM Studio/Ollama/chat endpoint; FFmpeg/FFprobe remain media-tool requirements.

## Existing libraries and voices

Audio, groups, notes, transcripts, dictionary corrections, weekly reports, exports and saved people stay in the same library. Upgrading does not regenerate completed meetings. Recovered old speech-stage jobs run natively. Native locale is pinned for each processing run.

Confirmed native samples still teach model-tagged voice profiles and produce reviewable similarity suggestions. Old untagged vectors never train or match native profiles. Missing/zero centroids allow manual naming. Numeric speaker labels are cleared when a new diarization run succeeds, preventing accidental reuse of old assignments.

Old model caches, HF credentials, obsolete setting rows and legacy profile files are deliberately left untouched for rollback. They are not read or used by 1.16. Back up the Library before explicitly reprocessing old recordings: installing an older app does not undo overwritten outputs. The separate comparison beta remains isolated.

## Building and distribution

Setup/start/rebuild/doctor no longer manage speech servers or Python. Builds clean generated JavaScript so deleted legacy modules cannot leak into the installer. Packaging includes only the native speech/capture helpers and required notices alongside Electron. Source builders need Node 22 and Xcode 26+ with the macOS 26 SDK; installed users do not.

GitHub releases contain source and notes, without binary assets. Local DMG/ZIP artifacts are built separately. Existing Apple Development signing is not Developer ID notarization. No user app is replaced or restarted during builds.

## Verification and limits

Full local CI passed: **1,320 tests**, type checks, build, lint, docs, capture-helper harness, Browse benchmark and all 11 UI fixtures plus the comparison UI. Actual source and signed packaged helpers completed the native pipeline on generated AAC. Package signature, payload and DMG/ZIP integrity checks passed. The DMG is **115 MiB, about 56% smaller** than 1.15.0. See the [verification report](../reviews/2026-10-16-native-only-release.md) for artifact hashes, exact tested state and limits.

Synthetic checks do not establish real-meeting accuracy for every language, accent, overlap or microphone. Broader quality/memory and speaker-score calibration remain follow-up work in #274; no universal speed/accuracy advantage is claimed.
