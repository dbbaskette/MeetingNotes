# MeetingNotes 1.22.1 — app audio survives a Bluetooth headset switch

## Fixed

A recording could capture your microphone but none of the meeting app's audio,
showing **Microphone is recording, but app audio is not detected**. It happened
when a Bluetooth headset such as AirPods was still in its music mode as
recording began: opening the headset's microphone moved it to call mode, macOS
paused audio on the headset for the change, and the app-audio capture did not
come back.

- The recorder now opens the microphone first and waits for it to deliver
  before it connects to the app's audio.
- While recording, it checks once a second that app audio is still arriving.
  If it has stopped, the recorder reconnects, retrying for as long as the
  recording runs. The gap is recorded as silence.
- The log records `recording:app-audio-stalled` and
  `recording:app-audio-recovered`, so a gap can be traced afterwards.

Recordings already made without app audio cannot be repaired.

## Upgrading

Install 1.22.1 over 1.22.0 or 1.21.x. No database schema migration is added.
Apple silicon and macOS 26+ remain required. Local installers use the existing
Apple Development signature, without Developer ID notarization. GitHub
publishes source and release notes without binary attachments.
