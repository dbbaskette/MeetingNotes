# MeetingNotes 1.14.0

Prepared 2026-10-07. **Not yet published.** This minor-version update combines
epics #242/#243 with the contributor work merged since the published 1.13.2 release.
It does not include the experimental remote-processing beta.

## Reliable capture and clearer setup

- Mic-only, app-only and mixed capture share a bounded native timeline with
  aligned stems, correctly placed gaps and coordinated file finalization.
  All entry points share one start reservation; URL dispatch is validated and
  pending requests can be cancelled safely.
- Stop failures retain truthful controls until helper exit is confirmed.
  Restart with All system audio is explicit and retains the chosen group.
- Source Refresh/retry keeps group intent and never starts capture implicitly.
  Browser/native detection latches avoid repeated banners and overlapping polls.
- Compact **Setup & health** links to the existing Settings sections without
  waking idle model services. An explicitly confirmed eight-second recording
  test is discarded without creating a meeting, processing it or exporting it.
- Shared Whisper model controls support downloads, progress and active choice.
  Interrupted/invalid downloads cannot replace an existing model; validation is
  structural, not a cryptographic checksum. Numeric stream peaks are optional.

## Guided processing and attention

- One prioritized status explains failures, speaker review and stale notes.
  Technical details retain the latest 20 failure/retry events.
- Up to three unresolved speakers appear inline, with access to the full panel;
  existing confidence rules, samples and bulk assignment remain authoritative.
- The complete **Needs attention** backlog is reachable from View all/overflow
  and paged in bounded categories instead of hiding older entries.
- Reprocessing retains original audio, existing notes/action-item history and
  local transcript snapshots before replacement.
- **Process recordings automatically when recording stops** defaults off.
  Only new usable, finalized built-in recordings qualify; imports, recovery,
  historical discovery and disposable tests do not silently enter the queue.

## Organized browsing, search, and Weekly tasks (#243)

- Retained in-session Library/Weekly navigation, keyboard selection, accessible
  busy/nested dialogs, New arrival markers, inline confirmed Move, recent
  destinations, compact group status badges, and revision-safe move Undo.
- Optional capture titles persist before helper startup and survive recovery
  and explicit restart; rename after Stop is optional. Generated titles cannot
  overwrite user intent.
- Cancellable owned search has truthful completion states and shared metadata
  facets plus explicitly saved named filters. Large transcripts use measured
  variable-height windowing with whole-text Find/copy/export and seeking.
- User-local weeks and content-aware narrative freshness cover summary/task/
  roster edits and concurrent regeneration. Weekly task edits roll back on
  failure; individual deleted tasks can be restored without losing metadata.
- Local whole-library backup includes consistent actual databases and audio,
  excludes model caches, validates a manifest, and restores only into a new
  destination. Backups contain private data and potentially settings secrets;
  store them privately. See [restore guide](../library-backup.md).

## Safer delivery and packaging

- Manual/automatic webhooks share ownership privacy and support summary-only
  delivery. Actual meeting IDs and retry-stable delivery UUIDs enable receiver
  deduplication. Deliberate resends get new IDs; delivery is at least once, not
  exactly once across restarts. Slack/Telegram dynamic text is escaped/bounded,
  redirects are rejected and failure logs remain redacted.
- Google Tasks searches every task-list page and coalesces concurrent creation.
- Packaging retains software graphics fallbacks, licenses and notices. A
  measured unsigned test baseline and actual normal/SwiftShader rendering plus
  offline sidecar inference replace assumptions about unused runtime resources.
  Test bundles are not a published installer.

## Upgrade, limitations and rollback

Automated verification: 1,166 source tests pass (six skipped), native synthetic
AAC/timeline/TTS checks, types/build/lint, Browse benchmark and UI fixtures pass.
The rebuilt 1.14.0 app renders a populated Library normally and with SwiftShader
on the granted host; on the ungranted clean Mac it renders the real permission
gate in both modes, without granting TCC. Packaged IPC, helper enumeration,
synthetic provider transport and real offline sidecar diarization also pass.
Exact source states, retained logs and unchanged dependency audit findings are
in the verification report; this is not a clean security-audit claim.

Requires macOS 14.2+ / Apple Silicon. Migration 21 adds local processing history;
migration 22 adds capture titles and group/task revision guards. #243 source/UI
verification is tracked separately in [its verification record](../epic-243-verification.md); prior
packaged results above are for #242, not a rebuilt #243 installer.
Existing recordings, groups, terminology and notes history are not relocated.
Back up the complete library with MeetingNotes closed before upgrading. App-only
downgrade does not undo migrations or external exports; schema rollback requires
the matching pre-upgrade library backup.

STT and diarization intentionally continue using the same mixed input.
Independent stem processing stays disabled pending real-device speech/overlap
evidence. The owner authorized merge and issue closure while deferring actual
microphone/call verification; synthetic tests do not establish that acceptance.
No real exporter account or real STT/summary provider inference was exercised.

See the [behavior and device-check guide](../reliable-capture-processing.md)
and [verification/packaging report](../epic-242-verification.md) for exact tested
states, evidence and limitations. A GitHub release and user installer must be
requested separately; merging this PR does not install or restart the app.
