# MeetingNotes 1.13.0-beta.1

Experimental source beta for macOS 14.2+ on Apple Silicon. Local processing remains the default; 1.12.0 remains the stable baseline. This branch publication does not include an installer, deploy a server, or publish a GitHub release.

## Optional remote processing

- Keep native recording, original audio, playback, Library, voice roster, speaker naming, edits and exports on the Mac.
- Choose a remote endpoint explicitly in Settings, test its identity and store the API token using macOS Keychain-backed encryption. There is no plaintext credential fallback.
- Upload the selected recording, then a labeled transcript after speaker review or skip. Download generated transcript, embeddings, summary and action items; the local voice roster is not uploaded.
- Persist upload/download progress and accepted jobs across network loss and application restarts. Show reconnect, retry, cancel and explicit local-fallback controls.
- Preserve local edits with revision checks and conflict review; archive displaced generation evidence before replacement. Reruns match speaker identities by compatible embeddings, never by recycled cluster labels.
- Provide a separate PostgreSQL/S3-backed processing API and worker, provider adapters, bounded jobs, leases, retention cleanup, container inputs and Cloud Foundry deployment instructions.

## Safety and compatibility

The local database changes are additive. Back up the library before beta testing. Original audio remains local. Switching the default back to local does not silently move an accepted remote job; finish or explicitly cancel it. Remote speaker matches require compatible model provenance, so unknown voices may need manual naming.

Native gate notifications are once per run and reset correctly for reruns and continuations. The privileged renderer now restricts navigation, popups and IPC senders.

## Verification and limitations

The implementation passed 949 desktop tests (five existing opt-in skips), 21 service tests with real local PostgreSQL/MinIO, typechecks, production build and isolated Electron UI checks. These used synthetic content, not real meeting recordings or production inference.

This beta is **not production security-qualified**. Known prerequisites remain: the existing desktop dependency advisories and production CSP migration; signed-user-session Keychain and native notification checks; a successful/scanned Linux image, model/license/performance qualification; and a selected Tanzu foundation with validated bindings, TLS and resource limits. The unsigned fixture reported Keychain encryption unavailable and correctly refused credential persistence. Do not treat an installer build as proof that those prerequisites passed.

See [the operator guide](../cloud-processing.md) for local synthetic setup, token rotation, retention, rollout and rollback. Do not upload sensitive recordings until the service and desktop have been qualified for your environment.
