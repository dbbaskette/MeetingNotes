# MeetingNotes 1.14.11

2026-10-16. This patch fixes stale meeting titles in the Library after a
rename in meeting details. GitHub publishes source and release notes only;
Apple Silicon installers are built locally.

## Meeting renames stay in sync

- Rename a meeting using its editable title or the details Actions menu,
  then go Back: the Library reflects the saved name without switching to
  All meetings and back or manually refreshing.
- The refresh includes expanded groups in Organized, All meetings,
  focused-group browsing, unchanged search results and Needs attention.
- Keep your current filter, expanded groups, loaded pages and scroll
  position. The Library is refreshed in place, not remounted or reset.
- Pending list requests are invalidated so an older response cannot become
  the final displayed result after the edit. Rejected renames do not publish
  unsaved titles; Library-row renaming still works.

The cause was a partial refresh when returning to the retained Library:
the flat list refreshed, but separately cached group pages and search
projections did not. Reactivation now uses the existing complete invalidation
path. See [issue #271](https://github.com/dbbaskette/MeetingNotes/issues/271)
and [PR #272](https://github.com/dbbaskette/MeetingNotes/pull/272).

## Install and check

The local DMG/ZIP targets **Apple Silicon, macOS 14.2+**, uses the existing
**Apple Development** signing identity and is **not notarized**. Building it
does not install it or restart MeetingNotes. Finish recording/processing and
quit the app before replacing it; keep a complete Library backup.

After installing, confirm version **1.14.11**. Expand a group, open a meeting,
rename it and go Back. The new title should appear without changing views,
with the same group expansion and scroll position. Repeat in All meetings or
a focused group if those are part of your normal workflow.

There is **no new database migration**: schema 24 and the permanent weekly
reports from [1.14.10](v1.14.10.md) remain unchanged. This patch does not change
capture, transcription, diarization, model configuration or integrations.
For app rollback, quit and reinstall the retained 1.14.10 installer. Do not
assume a downgrade to versions before 1.14.10 reverses its schema upgrade;
restore a complete matching pre-upgrade Library backup if that is needed.
Installer VM acceptance remains omitted by owner preference.
