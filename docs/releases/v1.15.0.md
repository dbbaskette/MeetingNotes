# MeetingNotes 1.15.0

2026-10-16. Apple transcription and SpeakerKit OSS are now integrated into the **full MeetingNotes app**, following the owner's successful beta evaluation. Recording, groups, speaker review, notes, action items, shared terminology corrections, PDF/Markdown exports, weekly reports and integrations remain available. GitHub publishes source and notes only; installers are built locally.

## Simpler local speech setup

- **Apple SpeechTranscriber + SpeakerKit OSS**, with a bundled Swift helper on Apple Silicon/macOS 26+.
- No Whisper download/server, Python environment, HF account/token or gated-model approval on this path. No Argmax Pro subscription or paid inference service.
- Explicit **Prepare native speech** provisions Apple language assets and roughly 11 MB of public speaker models, pinned and integrity-verified. Setup progress, cancellation and retry live in Processing Settings. Inference never downloads automatically or uploads meetings.
- Fresh supported Macs default to native speech. Existing installations retain their provider until they opt in. Legacy Whisper + pyannote remains available, including macOS 14.2+ compatibility.
- Native setup omits the Whisper/HF wizard steps; summaries still need a configured LLM and media operations still need FFmpeg. Native-only source setup is available through `./scripts/setup.sh --native`; the full installer retains legacy fallback.

## Keep the voice-memory workflow

Existing people and legacy voice vectors remain. Confirm native voices against the same roster to train model-tagged native profiles; future meetings show similarity-ranked candidates for confirmation. Native scores are not presented as probabilities and do not silently auto-assign people pending calibration.

Profiles from different SDK/model/representation spaces never mix, even if dimensions match. Missing/zero centroids allow manual naming rather than a normalization failure. New diarization labels never inherit an old run's numeric-label assignment. The isolated beta library/results remain untouched and are not automatically imported into the regular library.

## Full-app compatibility

Both native stages use the same primary mixed recording timeline. Real word timestamps are retained in raw output and grouped into readable speaker turns for display, phrase-level dictionary corrections and notes. The processing engine/language/model choice is pinned for each run and crash recovery. Explicit upstream reprocessing takes a new selection.

Historical meetings do not regenerate when the engine changes. Explicit reprocessing keeps the previous transcript snapshot and preserves existing notes/tasks through the existing history workflow where applicable. No new SQLite schema migration is introduced. Legacy matching, recording, exporters, Obsidian and summaries keep their existing paths.

## Upgrade and rollback

1. Finish active recording/processing, quit, and make a complete Library backup.
2. Install **MeetingNotes 1.15.0** when ready. A build does not replace/restart your installed app.
3. In **Settings → Processing**, select **Apple transcription + SpeakerKit**, then **Prepare native speech**. Check that both asset sets are ready.
4. Process a new meeting (or explicitly reprocess one old recording). Review voices, confirm saved people and continue to notes. Check playback, transcript attribution, corrections, action items and an export.
5. Keep the LLM and FFmpeg configured. Unsupported languages/assets fail visibly with setup guidance; there is no silent legacy/remote fallback.

To revert the speech engine, wait for processing/setup/queue to finish and choose Legacy. Existing legacy profiles remain usable; the new native artifacts are not automatically converted back. To roll back the application, quit and reinstall the retained 1.14.11 installer, switching to Legacy first. Reprocessing is a data change: use saved transcript/notes history or a matching complete backup to recover older results. Never restore a backup over a live Library.

The installer uses the existing Apple Development identity and is not notarized; it is not a Developer ID public-distribution build. No VM installer acceptance is claimed or required by the owner. Source/UI checks, native physical-device checks and artifact/signature results are documented in the [integration verification report](../reviews/2026-10-16-native-speech-integration.md).

## Evaluation limits

The owner reported the beta working well on their meetings. Synthetic short speech, repeated 75-minute coverage and small engine comparisons are useful functional evidence, not broad accuracy, overlap, memory or cross-meeting identification calibration. Native suggestions therefore remain human-confirmed, and legacy remains available. No universal speed/accuracy improvement over Whisper is claimed.
