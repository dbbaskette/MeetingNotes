# MeetingNotes 1.14.7

2026-10-08. Patch release for one-operation terminology corrections across a
meeting's transcript and summary. GitHub is a source-only release; Apple Silicon
DMG/ZIP installers are built locally, not uploaded as assets. The experimental
remote-processing beta remains separate.

## Define once, correct both

- **Correct terminology…** is available from either the Transcript or Summary
  tab. Enter a correction such as **Salsa → SLSA** once. The shared preview
  labels each occurrence and displays separate transcript and summary counts.
- **Apply to both** changes the selected occurrences in one operation. Uncheck
  occurrences to leave them alone; the button names the selected document(s).
  Existing summaries are edited directly—no LLM regeneration, no replacement
  of custom prose or formatting, and no action-item regeneration.
- **One Undo per combined operation** reverses the correction across both
  documents. Unrelated later summary edits are preserved. If a corrected passage
  has changed, Undo refuses the entire operation rather than guessing or
  reverting only one document. Earlier per-document history remains available.
- The existing shared dictionary is retained. **Remember** remains an explicit
  choice, scoped to the current group or all meetings. Suggestions are the
  default; automatic replacement in future generated text remains opt-in.
  Remembering a rule does not silently rewrite historical meetings.

## Safety and clarity

- Unsaved summary edits or active processing block corrections from either tab.
  Previews check both documents and applicable dictionary revisions before Apply.
- Writes use a durable combined journal and recoverable file replacement. A
  failure saving the second document rolls back the first when possible;
  interrupted operations recover together. Recovery preserves external edits
  rather than overwriting them.
- Raw transcription, audio, timestamps and speaker labels remain untouched.
  Corrections still survive speaker renaming/remerge.
- Correcting all matching wording in both documents does not introduce an
  unnecessary notes-refresh warning. Pre-existing warnings remain; leaving
  summary matches unchanged still marks notes as potentially stale.

## Upgrade and verification

No new schema migration, dependency update, data relocation or recording-state
change. The README and app/lockfile versions are updated together. Keep a complete
closed-app Library backup before upgrading. Building does not replace the
installed app or interrupt an active recording.

Verification covers the full source suite, production/type checks and isolated
synthetic Electron UI fixtures, including the combined correction flow. No real
meeting, microphone/call, account or vault acceptance is claimed. Installer VM
testing is intentionally omitted at the owner's request.

Requires macOS 14.2+ / Apple Silicon. Local installers use the existing Apple
Development signing identity and are **not notarized** because notarization is
not configured. This is not a notarized public-distribution build.
